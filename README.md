# Polymath Studio

공학 수식을 입력하고, 파라미터를 움직이며 해의 변화를 탐색하는 웹앱입니다. 현재 버전은 **선형 연립방정식(LEQ)** 에 집중합니다. React·TypeScript 화면과 Web Worker 안에서 실행되는 실제 WebAssembly 수치 솔버를 결합했습니다.

## 실행하기

Node.js 22 이상과 npm을 권장합니다. 저장소 디렉터리에서 실행하세요.

```sh
npm ci
npm run build:wasm
npm run dev
```

개발 서버가 터미널에 표시한 주소로 접속합니다. 배포용 정적 파일은 다음과 같이 만듭니다.

```sh
npm run build
npm run preview
```

`build`는 WAT → WASM 컴파일, TypeScript 검사, Vite 프로덕션 빌드를 순서대로 실행합니다. 결과물은 `dist/`에 생성됩니다. 별도의 Python 런타임이나 백엔드 서버는 필요하지 않습니다.

## 사용하기

1. **모델 정의**에 한 줄에 하나씩 방정식을 적습니다. 등록된 파라미터를 제외한 문자는 계산으로 구할 미지수입니다.
2. **파라미터 추가**에서 알려진 값의 이름과 현재 값을 등록합니다. 범위 설정 버튼에서 슬라이더의 최솟값·최댓값·간격을 바꿀 수 있습니다. 숫자 입력란의 값은 Enter 또는 포커스를 옮길 때 적용합니다.
3. 수식이나 파라미터를 수정하면 자동으로 계산합니다. **모델 풀기** 또는 `Ctrl/Cmd + Enter`로 다시 계산할 수도 있습니다.
4. **인터랙티브 시뮬레이션**에서 탐색 변수를 선택합니다. 그래프는 선택한 파라미터의 범위를 81개 지점에서 계산하며, **데이터 표와 CSV는 파라미터에 설정한 간격**을 따릅니다. 예를 들어 `0.2 ~ 0.8`, 간격 `0.01`이면 `0.2, 0.21, …, 0.8`의 61행이 생성됩니다. 다른 파라미터는 현재 값으로 유지합니다. 그래프 위의 지점을 가리키면 데이터 표에도 같은 조건의 해가 표시됩니다. 표의 행을 선택하면 그래프에서도 해당 지점을 표시합니다. 그래프와 표 모두 방향키로 탐색할 수 있고, 범례를 누르면 개별 곡선을 숨기거나 표시할 수 있습니다.
5. **해석 리포트**에서 입력 수식, 해, 잔차와 조건수를 확인합니다. 조건수 계산 방식은 ∞-norm 또는 2-norm(SVD) 중 선택할 수 있습니다. 계수 행렬과 방정식별 잔차는 **행렬·수치 검증 자세히 보기**를 펼치면 확인할 수 있습니다. 행렬은 계수의 부호나 누락된 항을 검토하는 공학적 검증 용도로 남겨 두었습니다. 리포트는 Markdown, 데이터는 CSV로 저장할 수 있습니다.

데이터 표에는 설정 간격으로 생성된 행만 표시하며, 현재 설정값을 별도 행으로 끼워 넣지 않습니다. 그래프 탐색도 데이터 행에 맞춰 선택되며, 곡선을 그리는 계산 지점은 별도로 유지합니다. 최댓값이 간격으로 나누어떨어지지 않으면 최댓값을 마지막 행으로 한 번 포함하고 마지막 구간이 짧다는 안내를 표시합니다. 표·CSV는 최대 2,000행이며, 초과할 경우 간격을 임의로 바꾸지 않고 조정 안내를 표시합니다. 이 경우에도 현재 해와 그래프는 사용할 수 있습니다.

계산된 유량이 음수인 경우처럼 수학적으로 가능한 해가 물리적으로는 적합하지 않을 수 있습니다. 모델의 단위와 운전 가능 범위는 사용자가 확인해야 합니다. 그래프는 정상상태의 **파라미터 변화 분석**이며, 시간에 따른 미분방정식 적분은 아닙니다.

## 직관적인 입력 문법

```text
# 두 식, 두 미지수
2x + 3y = 12
4x = 5 + y
```

| 입력                | 뜻                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `x`, `flow_A`, `T2` | 미지수 또는 파라미터 이름. 영문자로 시작하고 영문·숫자·밑줄을 사용하며 대소문자를 구분합니다. |
| `2x`, `2 x`, `2*x`  | 모두 숫자 2와 x의 곱입니다. 문자끼리의 곱셈은 `*`를 명시합니다.                               |
| `+`, `-`, `*`       | 덧셈, 뺄셈, 곱셈입니다. 미지수끼리의 곱은 허용하지 않습니다.                                  |
| `2*(x + y)`         | 괄호로 묶은 선형식에 상수를 곱합니다.                                                         |
| `x/2`, `x/R`        | 알려진 숫자나 파라미터로 나눕니다. 분모의 값은 0이 아니어야 합니다.                           |
| `.25`, `1.2e-3`     | 소수와 과학적 표기입니다. 소수점은 `.`을 사용합니다.                                          |
| `# 메모`            | `#` 뒤는 계산에 포함하지 않는 주석입니다.                                                     |

한 줄에는 완성된 등식 하나와 `=` 하나만 적습니다. 방정식 수와 미지수 수가 같아야 하며, 유일해를 얻으려면 식들이 독립적이어야 합니다. 중복되거나 모순되는 식은 진단 메시지를 표시합니다. `x*y`, `x^2`, `sin(x)`와 같은 비선형식은 지원하지 않습니다. 함수명과 조건문 예약어는 이름으로 사용할 수 없습니다.

### 원래 PolymathPlus LEQ와의 차이

첨부된 LEQ 명세의 기본 문법인 등식·계수 생략 표기·주석을 바탕으로 입력 경험을 확장했습니다. 원본 LEQ가 허용하지 않는 **괄호와 알려진 값으로의 나눗셈**도 선형성이 유지되는 경우 지원합니다. 상수끼리의 거듭제곱 계산도 가능하지만 미지수의 비선형 거듭제곱은 거부합니다.

파라미터는 수식의 대입문과 구분하여 별도 패널에 등록합니다. 예를 들어 `F`를 파라미터에 등록한 다음 `x + y = F`라고 적으면 x와 y가 미지수입니다. 수식에 `F = 100`을 추가하면 그 줄도 연립방정식 하나로 처리합니다. 원본 소프트웨어의 전체 문법이나 파일 형식과 호환되는 구현은 아닙니다.

## 예제

앱의 **예제 불러오기**에서 다음 네 모델을 선택할 수 있습니다.

| 모델                   | 기본 조건에서의 해        |
| ---------------------- | ------------------------- |
| 두 유체의 혼합 공정    | `x = 50`, `y = 50`        |
| 처음 만나는 연립방정식 | `x = 27/14`, `y = 19/7`   |
| 세 미지수의 균형       | `x = 3`, `y = 4`, `z = 5` |
| 직렬 저항의 전압 분배  | `U1 = 4`, `U2 = 8`        |

기본 혼합 모델은 다음 식을 사용합니다.

```text
# 전체 유량과 성분 물질수지
x + y = F
c_A*x + c_B*y = c_T*F
```

파라미터는 `F = 100`, `c_A = 0.2`, `c_B = 0.8`, `c_T = 0.5`입니다. 농도는 0~1의 분율입니다. F는 총유량, c_A와 c_B는 두 유체의 농도, c_T는 목표 농도입니다. x와 y는 각 유체의 유량이며 F와 같은 단위를 사용합니다.

## 계산 아키텍처

```text
수식 입력 → 안전한 파서·AST 캐시 → 선형 계수 행렬 A·x = b
                                      ↓
React 상태 ← 요청 번호로 최신 결과 선택 ← Web Worker
    ↓                                   ↓
해·리포트·SVG 그래프·표         WebAssembly 부분 피벗 가우스 소거
```

- `src/engine/index.ts`: 문자열을 토큰과 AST로 파싱하고 캐시합니다. `eval`이나 동적 JavaScript 실행 없이 파라미터를 대입해 선형성을 검사하고 행렬로 변환합니다. 64개 미지수와 64개 방정식까지 지원합니다.
- `src/engine/solver.wat`: 64비트 부동소수점 연산으로 부분 피벗팅 가우스 소거를 실행하는 WebAssembly 텍스트 소스입니다. 행별 정규화를 거쳐 계산합니다.
- `scripts/build-wasm.mjs`: npm 패키지 `wabt`로 WAT를 검증·컴파일해 `public/solver.wasm`을 생성합니다. Emscripten이나 C 컴파일러는 필요하지 않습니다.
- `src/engine/conditioning.ts`: 원래 계수 행렬의 ∞-norm·직접 SVD 2-norm 조건수와 민감도 참고 범위를 계산합니다.
- `src/engine/sweep.ts`: 그래프 계산 지점과 설정 간격의 데이터셋을 분리합니다. 십진수 간격은 정수 격자로 계산해 누적 오차를 피하고, 최댓값과 행 수 제한을 처리합니다.
- `src/engine/solver.worker.ts`: UI 스레드 밖에서 현재 조건과 파라미터 범위의 해를 계산합니다. 범위 안의 해를 구할 수 없는 지점은 별도로 표시하여 곡선을 이어 그리지 않습니다.
- `src/App.tsx`: 입력을 잠시 모아 계산 요청을 보내고, 이전 요청의 응답이 최신 결과를 덮어쓰지 않게 요청 번호를 확인합니다. 절대 잔차와 ∞-norm 조건수로 수치 상태를 안내합니다.
- `src/components/SolutionChart.tsx`: 반응형 SVG 그래프입니다. 그래프 탐색과 데이터 표가 같은 선택 상태를 공유합니다.

기본 계산 엔진은 WebAssembly입니다. WASM을 불러오거나 실행할 수 없는 환경에서는 같은 부분 피벗팅 알고리즘의 JavaScript 구현으로 전환하며, 화면의 엔진 표시와 경고에 이를 명시합니다. SymPy·NumPy·SciPy나 AI 모델은 사용하지 않습니다.

## 조건수와 민감도

**해석 리포트 → 조건수 계산 방식**에서 다음 방법을 선택할 수 있습니다.

- **∞-norm**: `κ∞(A) = ||A||∞ · ||A⁻¹||∞`. 행렬과 역행렬의 최대 절댓값 행 합을 사용합니다. 기존 방식이며 기본값입니다.
- **2-norm · SVD**: `κ₂(A) = σmax(A) / σmin(A)`. `ml-matrix`의 직접 특이값 분해로 구합니다. 정밀도 손실을 키울 수 있는 `AᵀA`를 만들어 계산하지 않습니다.

두 값은 서로 다른 norm으로 민감도를 측정하므로 다를 수 있습니다. 2-norm 선택이 해 자체의 계산 정밀도를 높이는 것은 아닙니다. 조건수는 행별 정규화 전의 입력 계수 행렬 A를 기준으로 계산하며, 단위나 변수 스케일이 달라지면 값도 달라질 수 있습니다. 선택한 방식은 로컬 자동 저장·프로젝트 JSON·Markdown 리포트에 반영됩니다. 기존 프로젝트 파일에 선택 정보가 없으면 ∞-norm을 사용합니다.

색상과 문구는 다음 **참고 범위**를 함께 표시합니다.

| 조건수 κ         | 표시             |
| ---------------- | ---------------- |
| 1 ≤ κ < 10⁴      | 초록 · 안정      |
| 10⁴ ≤ κ < 10⁸    | 노랑 · 민감      |
| κ ≥ 10⁸ (∞ 포함) | 주황 · 매우 민감 |
| 계산 실패        | 회색 · 판정 불가 |

이 구분은 정확도를 보장하는 절대 기준이 아닙니다. 실제 신뢰도는 측정 오차·유효숫자·단위에 따라 해석해야 하며, 작은 잔차도 정확한 해를 보장하지 않습니다. SVD 진단만 실패한 경우에는 조건수를 꾸며 내지 않고 판정 불가를 표시하며, 계산된 해와 잔차는 유지합니다.

조건수는 현재 설정의 결과에만 계산합니다. 그래프와 표의 각 지점은 조건수 진단을 생략하여, 반복적인 SVD나 역행렬 계산이 슬라이더 반응성을 낮추지 않도록 했습니다. 이 지점들에서는 해의 값만 사용합니다.

## 저장과 네트워크

현재 모델은 브라우저 `localStorage`에 자동 저장되며 새로고침 후 복원됩니다. 저장소 접근이 막혀 있으면 자동 저장 불가 상태가 표시됩니다. **프로젝트 저장**은 수식·파라미터·범위·이름이 포함된 JSON을 내려받고, **불러오기**는 그 JSON을 검증해 복원합니다. 다른 예제를 선택하거나 파일을 불러오면 현재 모델을 교체하므로 필요한 모델은 먼저 JSON으로 저장하세요.

모델 계산과 저장에는 백엔드 연결이 필요하지 않습니다. 앱과 WASM이 모두 로드된 뒤에는 네트워크 없이 현재 페이지에서 계산할 수 있습니다. 서비스 워커, 오프라인 캐시, 설치 가능한 PWA 기능은 구현하지 않았으므로 오프라인 새로고침이나 최초 접속까지 보장하지는 않습니다. 프로젝트 파일과 로컬 자동 저장 내용은 암호화된 비밀 저장소가 아닙니다.

## 검증

```sh
npm test
npm run build
npm run test:e2e
```

`npm test`는 WASM을 다시 빌드하고 Vitest 수치·파서 테스트를 실행합니다. 알려진 연립방정식, 파라미터 대입, 비선형식 거부, 특이/모순 행렬, 단위 크기 차이, 실제 WASM 실행을 검증합니다.

Playwright 테스트는 개발 서버를 시작하여 실제 브라우저의 WASM 계산, 슬라이더 갱신, 예제 전환, 그래프·표 연결, 행렬·리포트·다운로드, 자동 저장, 화면 크기 대응을 확인합니다. 현재 클라우드에서는 `/usr/bin/chromium`을 사용합니다. 다른 환경에서는 `npx playwright install chromium`으로 브라우저를 설치하거나 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 설치된 Chromium 경로를 지정할 수 있습니다.

## 이번 범위

LEQ 입력·계산, 파라미터 시뮬레이션, 수치 리포트, 로컬 저장과 파일 내보내기를 구현한 프로토타입입니다. ODE·NLE·회귀/데이터 분석 탭은 아직 활성화하지 않았습니다. 단위 자동 검증, 기호식 풀이, 시간 적분, 3D 렌더링, 사용자 계정·클라우드 동기화, AI 모델 생성은 포함하지 않습니다.
